## Confirmed findings

1. **P1: No single policy enters public 2.5D pipeline.** `src/mesher/contracts/process_flow_2_5d.py:39-55,206-219` allows only `regionMeshing` as optional setting, rejects a `tolerance` setting. Unit is `um` at line 15, so intended 0.001 means 0.001 um (1 nm). Public `src/mesher/mesh25d/__init__.py:12-32`, pipeline `pipeline.py:20-53`, and CLI `process_flow/worker.py:21-45` expose no tolerance. `geometry/context.py:21-31` invokes `extract_pattern` default. `geometry/patterns.py:13,31-49` dedupes faces at 1e-6, independently returns `coordinate_tolerance=1e-3` and `clearance_tolerance=1e-6`. Even its explicit `tolerance` argument controls only dedupe, not the returned two settings. Config can therefore appear to use 0.001 while upstream normalization and downstream algorithms do not.

2. **P1: A small KOZ silently reduces the entire model's tolerance.** `src/mesher/mesh25d/geometry/koz.py:23-33` recursively computes `min(default, every_positive_koz/100)`. `geometry/patterns.py:35,48` applies that both to dedupe and returned planar coordinate/clearance settings. Verified: no KOZ => coordinate=.001; KOZ .05 => .0005; KOZ .0001 => .000001. This is global, even for unrelated geometry; no local feature policy or diagnostic. `plan2d.py:97-103` further reduces circle clearance by planar_size/100; `circle_planning.py:360-382` can shrink mesh size from tiny KOZ gaps. An environment requiring 0.001 cannot be enforced by changing one default.

3. **P1: Z geometry, controls, layer grouping, and extrusion use incompatible equivalence rules.** `geometry/primitives.py:51-68` rounds geometry endpoints to 3 decimal places. `meshcontrol/methods.py:56-64,154-161` resolves raw reference bounds without rounding. `plan3d.py:36-61` uses exact float dictionary/set keys and comparisons; `mesh3d/extrusion.py:503-507,547-548` rounds interval lengths to 5 decimals. Verified full pipeline: Z_POINT .5 and .5004 generate a real .0004-thick solid (3 solids versus 2 for .5 only). Geometry endpoints 1.000499 and 1.000501 differ by .000002 yet round to 1.0 and 1.001. Box thk=.0004 silently returns an empty mesh (0 elements); no collapsed-feature diagnostic. A reference to raw z_max=.5004 resolves .5004 but same body's material END event is .5; planner clips away the reference beyond model_end. This is not fixed by replacing `round(...,3)` with proximity equality: clusters need deterministic representatives and preserved material event ordering.

4. **P1: Ordinary binary floating-point division changes layer counts.** `src/mesher/mesh3d/extrusion.py:503-507` computes floor(distance/element_size); `src/mesher/mesh25d/plan2d.py:235-250` similarly floors subdivision counts. Verified .3/.1 is below 3 in float64: full box pipeline produces Z levels [0,.15,.3] (2 layers) instead of [0,.1,.2,.3]; `_section_avg_lines([0,.3],.1,...)` produces only .15. Changing interval end to .300000001 changes XY subdivision from 2 to 3, despite only 1e-9 perturbation. `meshcontrol/methods.py:227-237` already tries a near-integer numerical guard with rel_tol=1e-12, but extrusion and XY planner do not share it. The guard's relative tolerance is numerical, not a geometric distance, and should not be globally replaced by .001.

5. **P1: Material selection uses 0.01 and inconsistent shape semantics.** `src/mesher/mesh3d/extrusion.py:256-305,371,419,453-458` uses default tolerance .01 (10x intended) for bodies and features. KOZ path independently uses min(.01,koz/100), potentially far below .001. Verified a complete cell spanning x=1.002..1.004 is selected by face BOX [0,0,1,1] by default, but rejected at .001. The Polygon path passes Matplotlib radius=tolerance while BOX/CIRCLE expand by full tolerance; radius represents total stroke width, so geometric expansion is half. Verified same cell reaching x=1.00075 is selected by BOX at .001 and rejected by equivalent POLYGON at .001. Also box inequalities are strict while circle uses <=; inclusive threshold policy is undefined. Material errors can remain silent even when meshing succeeds.

6. **P1: Circle topology planning still rejects sub-.001 positional jitter.** `src/mesher/mesh25d/circle_planning.py:21-22,54-85,130-140,188-220,309-357` uses hardcoded 1e-6 for symmetry-center checks, concentricity, containment, annulus checks, and band clearance. Verified center x=.0004 versus symmetry axis x=0 errors; x=0 succeeds. `_collect_circle_patterns` at 89-95 uses raw dataclass float set keys, after upstream dedupe at 1e-6; raw source/KOZ mappings in `geometry/patterns.py:52-80` and `plan2d.py:77-78` likewise need canonical identities if coordinates are normalized.

7. **P1/P2: Axis aligned polygon requirements use exact coordinate equality.** `src/mesher/mesh25d/region_adapter.py:119-140` removes only exactly repeated coordinates/closure and insists every edge exactly horizontal/vertical, despite receiving coordinate_tolerance later. Verified one corner displaced .0004 yields `QuadLayerError: polygon edges must be exactly axis aligned`. `circle_planning.py:246-264` silently drops that near-horizontal guide (3 segments instead of 4). Both should consume a common normalized geometry representation, not disagree after grid coordinates are coalesced.

8. **P1: Translation changes geometry retention and material density due cancellation.** `src/mesher/mesh25d/domain.py:201-225,274-291` uses untranslated shoelace area and 64*machine_epsilon*absolute_world_coordinate^2 as cutoff. Verified a 1x1 polygon with half retained by symmetry: at origin area=.5 and retained; shifted to 1e7 area=.5 but cutoff=1.421 => whole feature discarded; shifted to 1e8 computed area=0 and cutoff=142.1. `src/mesher/mesh3d/extrusion.py:201-221` repeats untranslated shoelace: two 1x1 cells shifted to 1e8 get areas [0,0]. With density25, `_assign_metal` selects both zero-area cells, whereas original selects none. `_signed_area` at 249-254 has the same cancellation exposure and controls polygon inclusion offset direction. These are numerical robustness issues; cannot fix by setting an area threshold to .001 (wrong dimension). Translate to local origin / robust predicates; distinguish numerical cancellation bound from user geometric policy. Large-coordinate qualification matters: these probes use 1e7–1e8 um, not case1's proven scale.

9. **P2: Z remainder tolerance .01 is disconnected from .001.** `src/mesher/meshcontrol/methods.py:188-195,227-237,243-286` defaults min_dis=.01, and `src/mesher/mesh25d/controls.py:47-52` never overrides it. Verified TOP section 0..1.005 with size1 suppresses .005 remainder by default; min_dis=.001 creates [0,1],[1,1.005]. Geometric relevance of a remainder must be a named policy; blanket replacement of every numeric threshold is inappropriate.

10. **P2: CDB serializing at 12 significant digits can exceed .001 error.** `src/mesher/process_flow/exporters/cdb.py:58-63,166-167` uses `.12g`. Verified 1000000000.004 serializes to 1000000000, abs error ~.004. At typical smaller coordinate values it is fine; lack of declared coordinate range means precision guarantee is absent. Use float64 roundtrip text (`repr` / .17g), verify exported coordinates/topology, and include tolerance/unit policy version metadata.

## Further integration risks (static evidence, not independently demonstrated failures)

- `src/mesher/mesh25d/plan2d.py:35-40,278-295` forwards projection=.2h, guide=max(.001h,1.0), merge=.002h, minimum_area=.0004*h^2 to circle imprint. Guide minimum 1.0 is 1000x required geometric tolerance, and is documented as identifying on-guide nodes; must decide whether it is actually an algorithm search width. Projection/merge are algorithm operation distances, minimum_area has units length^2, ratios dimensionless. They require named semantics and bounds; do not mechanically set all to .001. Existing `tests/integration/mesh25d/test_builder.py:1043-1065` explicitly pins current formulas.
- `src/mesher/mesh25d/plan2d.py:344-351` calls circular extension without precision policy. Underlying circular code covered by sibling audit.
- `src/mesher/mesh25d/region_adapter.py:305-308,326-329,358-360` passes coordinate_tolerance to seed and final full adapter, but intermediate `generate_layer_adaptive_mesh` receives no tolerance argument. Verify API feasibility with adapter audit; policy must survive the intermediate stage as well.
- `src/mesher/mesh25d/domain.py:145-173,228-271,294-307` uses exact clipping/inside/outside comparisons. Therefore .0004 slivers and near-tangent circles may be retained as positive area even if source-normalization policy considers boundaries coincident. Need normalize before clipping with explicit boundary/contact semantics; not all exact comparisons are erroneous after canonicalization.
- `src/mesher/mesh25d/geometry/koz.py:36-82` makes exact inset/empty decisions and uses Shapely polygon buffer/symmetric_difference without a project precision model. Sub-tolerance surviving KOZ strips need explicit reject/retain policy. Shapely doubles are not automatically 0.001 geometry.
- `src/mesher/mesh25d/region_adapter.py:61-75,143-167,201-210,268-282` uses Shapely predicates and distances plus explicit tolerance checks; this is more robust than exact equality but topology may differ if old coordinates and snapped grid coexist. Equality of boundary ID cycles at 272-274 is correct discrete topology comparison and should remain exact.
- `src/mesher/mesh3d/model.py:32-107` validates shapes/metadata but no geometric postconditions (finite coordinates, positive volumes/Jacobians, collapsed feature/layer checks). Thus earlier errors can reach export. Introduce policy-aware validation outside or alongside generic storage constructor rather than embedding all meshing assumptions in a data class.

## Migration design and acceptance plan

1. Define versioned `GeometryTolerance` / precision policy, immutable per build. Document length unit, .001 absolute coincidence metric and inclusive/exclusive rules, role of normalization, supported coordinate magnitude, and treatment of unresolved features. Numerical roundoff, angle/dimensionless predicates, element quality, projection distance, area and volume are separate named quantities with correct units. .001 cannot be copied into dot/cross/area values.
2. Add policy to JSON schema/public build/worker; resolve once and thread through preparation, controls, XY grid/adapter/circle plans, Z planning, assignments, extrusion, and exports. Emit effective values and policy version in progress/output. Remove silent global KOZ-driven reduction; sub-resolution source features need explicit actionable handling.
3. Canonicalize source coordinates/axes/endpoints and feature identity consistently before dedupe, reference resolution, circle planning, and Z event grouping. Define deterministic clustering that bounds movement/cluster diameter; near-equality is not transitive, so naive union-find can swallow chains. Preserve provenance and displacement; diagnose collisions/collapsed features. Normalize nearly axis aligned edges within tolerance; do not independently snap each downstream copy.
4. Make Z boundary planner canonical; coalesce near-equivalent events/controls while retaining END-before-START and priority semantics. Reject or explicitly handle collapsed nonzero material intervals, instead of silently producing empty mesh. Share a stable integer subdivision routine for XY/Z (near-integer numerical check + deliberate floor/ceil policy). Derive exact last endpoint rather than rounding lengths.
5. Correct shape membership to one physical distance metric; account for Polygon Path's radius/2 semantics or replace with shared distance/predicate logic. Apply same policy to body/material/KOZ selection. Keep computational search widths explicit, separate from coincidence tests.
6. Use local coordinates for area/winding and numerical error estimates; do not make source geometry disappear solely because translated away from origin. Validate final signed volumes/Jacobians/connectivity with dimensionally sound thresholds. Maintain discrete node-ID equality.
7. Add regression matrix: case1; jitter at 0, ±.0001, ±.000999, ±.001, ±.001001; tolerance-boundary vs snapping-cell-boundary cases; reordered input; chained near-coincident features; KOZ below/equal/above tolerance; symmetry tangent/center jitter; BOX vs equivalent POLYGON/CIRCLE membership; reference vs absolute Z; .3/.1 subdivision; translated models; CDB roundtrip at largest supported coordinates. Assert topology/material/volume and diagnostics, not only absence of exceptions.
8. Stage rollout: freeze failing fixtures + baseline topology/material metrics; introduce contract and shared helpers; migrate preprocessing/Z; adapter/circles; material selection and numerical local frames; export; then compare large known models. Existing tests that enforce .01 / 1e-6 / guide1.0 behavior need deliberate review rather than blind golden-output regeneration.
